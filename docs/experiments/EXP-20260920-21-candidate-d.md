## 目的

**v49 / v50 系（V47 系の後継）に勝ち越せるようにする。** ただし v6・v7 の強みであるコピー対策を崩さない。
根拠は EXP-20260920-19：本番の15敗のうち8件が「個数は同じで単価だけ負ける＝売り時の差」で、
中身は終盤の牛乳・いちご。負けの6件は −300 以内で、**レーティングは勝敗しか見ない**（doc 08 §2）ため、
小さい負けを勝ちに変えるのがいちばん安い。

## 仕組みの特定（v9/4 の RACEGATE）

v9/4 には `_r36_reserve`（テープの将来の売りを前倒しする予約）と、その入口に **RACEGATE** がある。

```
V9_RACEGATE_BASE = {"WHEAT": 25, ..., "STRAWBERRY": 120, "MILK": 160, "WOOL": 200, ...}
glutted = {品目 | 現在価格 <= 基準価格}     # 基準以下の品目は予約しない＝テープどおりの時刻に売る
```

**終盤の牛乳（基準160）は 30〜80、いちご（基準120）は 15〜50 で、必ず基準以下。**
つまり**終盤はこの2品目の予約が常に止まっており、前倒しが効かない。**
相手（v49 など）は値が戻ったところを先に取りに来るので、1〜2時間の差で負ける（EXP-20260920-19 の実例）。

## 方法

- v7 の末尾に層を足すだけ（v9/4 原本も v7 の層も書き換えない）。組み立て：スクラッチパッドの `build_d.py`。
- 層の動き：**終盤（step >= START）だけ、指定品目を `V9_RACEGATE_BASE` から一時的に外して**（呼び出しの間だけ 0 にする）
  v9/4 自身の予約を効かせる。**価格が MINPRICE 未満のときは何もしない**（底値での投げ売りを避ける）。
- seed は用途ごとに分ける：**選別 121〜140 / 評価 141〜200 / 直接対決 201〜240**。受け入れ条件は**未使用の seed** で行う。

### d7 は v7 に勝てない（設計上そうなる）

d7 と v7 は 167ステップまで完全に同じなので、**互いをコピーと判定して D 層が止まり、ミラーになる**（40試合中34分）。
**「v7 に勝つ」と「コピー戦を崩さない」は両立しない。** d1 は v7 に 66勝46敗だったが、その勝ちは
コピー対策を乱すことと引き換えだった。**2026-09-20、ユーザーが「v7 に勝つ必要はない」と判断。**

## 分かったこと

1. **終盤の売り負けの原因は RACEGATE だった。** 値崩れした品目は予約が止まるため、テープどおりの時刻にしか売れない。
2. **直し方は「終盤だけ・牛乳といちごだけ・底値では売らない」が最良。** 品目を広げても価格の下限を下げても悪化する。
3. **コピー戦には触らないこと。** 候補A・A2 が握っている領域に D を足すと壊れる。
4. **金額ではなく勝敗で測ること。** 先に売ると総額は減ることが多いが、僅差の負けを勝ちに変える。
