## Telemetry / interpretation

The intended mechanism is confirmed at the instrumentation level: known and fresh tests reduced R37 evaluations by approximately 13-17% with zero observed action/reward mismatches across 48 exact-equivalence cases. However, wall-clock runtime did not reliably improve. The second, historically comparable runtime run was materially slower at median and p99 and produced 7 calls above 200 ms.

Therefore the lesson is: **R37 evaluation-count reduction is not a sufficient proxy for end-to-end agent latency in this implementation/environment.** Any future runtime candidate should profile which work dominates the remaining call path before reusing this guard as a promotion candidate.

## Decision

**REJECT v157. Do not promote. Formal champion remains v153.**

Reason:

1. exact action/reward equivalence passed on known and fresh seeds;
2. R37 evaluations decreased materially;
3. first runtime gate failed absolute worst-call NFR;
4. historical-method runtime recheck also failed absolute worst-call NFR and showed slower median/p95/p99/worst versus v153;
5. project rules require runtime NFR and no material runtime regression for promotion.

The hard-opponent harness failure is separately classified as a validation-harness bug and is not the rejection cause.

## Next hypothesis

Do not retry the same `parent_changed` guard as-is. Profile the R37 call path and identify whether allocation, wrapper copying, telemetry, market pricing, or GC pressure dominates end-to-end latency. A next runtime candidate should be a distinct, small change with its own exact-equivalence proof and should benchmark using the same historical-method harness before broader evaluation.
