# EXP-20260922-51: v25へR148 overflow回収を単独移植

状態: Implemented / 評価完了・不採用（発火0）

関連: EXP-20260922-50、roadmap 3-36

## 仮説

Pipe19の改善要素のうちR148だけをv25の最終層へ追加すると、夜明けの倉庫超過で消えるはずの作物を安全に現金化できる。ADVやPipe19本体は移植しない。

## 実装条件

- 候補名は `v26_r148_overflow` とし、v25を完全な親にする。
- step 23 mod 24だけで判定する。
- 元の注文が予算内で、市場注文枠に空きがある場合だけ検討する。
- 単位行動と既存市場注文を適用した後、夜明け配送で実際に失われる貨物がある場合だけ発火する。
- 追加売却後の夜明け後在庫ベクトルが追加前と完全一致する最大の売却案だけを採用する。
- 例外時は必ずv25の元アクションへ戻す。
- Apache-2.0の出典をSOURCE.mdへ記録する。

## 受け入れ条件

- v25の先頭バイトが完全一致し、差分が末尾のR148層だけである。
- focused testとpreflightが全項目合格し、通常720 stepの例外が0件。
- v25同一seed回帰で、非発火試合は出力・最終金額が一致する。
- JAXA、Order Book、Pipe19を含む代表パネルで、例外・家畜逃走を増やさない。
- 発火試合は発火回数・回収個数・最終損益を記録する。
- 明確な改善がなければ提出候補には採用しない。

## 考察

R148は単体機能として安全に移植できたが、代表5相手・50試合では一度も発火しなかった。v25は夜明け時の倉庫超過を既存層ですでに避けており、Pipe19で見えた改善はR148単独ではなくADV、基盤差、または相互作用に由来する可能性が高い。実効性がない状態で提出コードを増やす理由がないため不採用とし、v25を維持する。
