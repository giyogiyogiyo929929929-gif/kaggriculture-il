## 仮説

EXP-20260918-01 で出した上位勢の「型」（序盤の買い物、土地購入日、作物の遷移、雇用数）を
そのままルール化すれば、`starter` / `random` を大きく上回るベースラインになる。

## 設定

- 実装：`main.py` + `agent/features.py` / `agent/macro.py` / `agent/execute.py`
- 評価：`seed = 1..5` × 席入れ替え = 10戦を `starter` と `random` それぞれに対して実施
- テスト：`tests\test_agent_baseline.py`（23件。うち1件は720ターンの実戦テスト）

|---|---|---|---|

| `random` | **10/10** | 61,323 | +61,121 ± 2,308 |

- 最終日の家畜：中央値17頭

## 途中で見つかった不具合（すべて実測で確認して修正）

最初の実装は `starter` に **16 対 3,756** で大敗した。原因は5つ。

1. **ユニットが往復して何も終わらない。**
   ユニットごとに順番に「最寄りの未割り当てタスク」を選ぶと、毎ターン担当が入れ替わり、
   WEST → EAST → WEST と往復していた。
   → 全ユニット × 全タスクを (優先度, 距離) で並べて上から確定する方式に変更。
2. **家畜を置けないまま買い続けて資金が溶ける。**
   置き場（COOP / PASTURE）が無いのに shed の家畜を `PICKUP` し、置けずに抱え込み、
   shed の在庫だけを見ていたマクロ層が「まだ足りない」と判断して買い増していた。
   → 置き場の空きぶんだけ拾う、手持ちも含めて頭数を数える、足りない置き場を先に建てる。
3. **家畜の餓死。** 水やりを給餌より優先していたため、餌を持った係が畑に取られて
   家畜が2日連続で未給餌になり逃走、買い直しで資金が尽きた（1頭400〜500）。
   → `FEED` を最優先に。
4. **餌の備蓄が倉庫を食い潰す。** 「頭数 × 3 × 2日分」を残す設計にしていたため、
   家畜16頭で96個を抱え、shed 上限100を占有して収穫物が破棄されていた。
   → 実際の消費は1頭1日1個。`頭数 × 1 + 12` に変更。
5. **植えられない種を買っていた。** 空きタイル3枚に対して STRAWBERRY の種を27個買って死蔵。
   → 種の購入上限を空きタイル数に。植え付けの優先度も `CARE` より上に。

修正の効果（`seed=7`、対 `starter`）：16 → 8,574 → 39,495 → 43,045。

## 考察

- 上位勢の「型」は数字としては正しく再現できている（day13 の MELON 一斉収穫、
  STRAWBERRY 31〜33枚、家畜14〜17頭、土地3枚）。それでも上位勢の61%にとどまる。
- 差の出どころは**実行効率**である可能性が高い。EXP-20260918-01 で
  「マクロ行動では勝敗を説明できない」と出たことと整合する。
  今回、同じマクロ方針のまま実行層の割り当てを直しただけで 16 → 43,045 に変わった。
  **実行層が性能を支配している**という ADR-0001 の想定は、良い意味でも悪い意味でも当たっている。
- 未着手の伸びしろ：`FERTILIZE` 未使用、価格を見ない売却（$1 でも売る）、
  4枚目の土地を買わない、終盤に植えきれない。
