## 仮説

席入れ替えのペア比較を自動化すれば、エージェントの改善を「差の平均 ± 標準誤差」で判定できる。
あわせて健全性（枯死・家畜の逃走・shed 溢れ）を数えれば、勝敗に出る前に問題を見つけられる。

## 設定

- 実装：`scripts\eval.py`（doc 05 §7）
- 計測：`eval.py main.py starter -n 5`（5ペア = 10試合、720ターン）
- 健全性は**連続する2ステップのタイル比較**で数える（doc 05 §2.1）。
  行動ログではなく盤面の遷移を見るので、成功した行動だけが数えられる。

## 結果

```
対戦: main.py vs starter   ペア数 5（10試合、-j 4）
勝敗          : 5勝 0敗 0分（ペア単位）
ペア差        : +58,913 ± 2,194（平均 ± 標準誤差）
最終所持金    : A 中央値 63,793 / B 中央値 3,605
1ターン推論   : A 中央値 1.3ms 最悪 5.0ms（-j 1 で計測）
例外          : A 0件 / B 0件
健全性(A)     : 植え付け 54 → 収穫 31 / 枯死 14（weed自然発生 8）/ 家畜逃走 4 / 最終shed 30
健全性(B)     : 植え付け 10 → 収穫 9 / 枯死 0（weed自然発生 3）/ 家畜逃走 0 / 最終shed 0
```

- EXP-20260919-01 の数字（5勝0敗、ペア差 +58,913、中央値 63,793）を**完全に再現**した。
- 並列化の効果：`-j 1` で 47.8秒 → `-j 4` で **20.9秒（2.3倍）**。結果は一致。
  ただし並列時は推論時間の最悪値が 5.0ms → 17.3ms に伸びるので、
  **時間の判定は `-j 1` で行う**（doc 05 §1.2）。
- 組み込みの `random` は再現しない（`random_agent` が毎ターン無シードの `random.Random()` を作る。
  実装で確認）。再現性が要る比較には使えない。

## 判明した未達項目（0-6 の判定が誤っていた）

| 項目 | 0-6 での判定 | 実測 | 何を見落としたか |
|---|---|---|---|
| 家畜の逃走ゼロ | 達成 | **平均4頭/試合** | 最終盤面の頭数（17頭）だけを見ていた。逃げた分を買い直していたので頭数では分からない |
| 枯死が植え付けの5%以下 | 達成扱い（保留） | **54件中14件 = 26%** | weed の総数しか見ておらず、自然発生（8件）に紛れていた |

どちらも「最終状態のスナップショット」では見えず、**遷移を数えて初めて見えた**。
04 §5.5 のチェックを未達に戻し、§5.6 に改善候補を書いた。

## 考察

- 評価ツールを先に作らずにベースラインを「達成」と判定したのは早かった。
  最終状態だけを見る指標は、**壊れてから作り直している状態**を見逃す。
- 逃走4頭 ≒ 1,600〜2,000 の損失、枯死14件 ≒ 種代1,400 に加えて収穫機会の損失。

> **訂正（2026-09-19、EXP-20260919-06）**：ここでの「枯死」の数値は誤り。
> 指標が `PLANT→WEED` を一括で数えており、**ongoing 作物（STRAWBERRY）が
> 全部収穫し終えて寿命で消える正常な遷移**まで枯死に含めていた。
> 実測では水切れによる枯死も未収穫損失も **0件**。この項目は未達ではない。

  上位勢との差（63,793 対 103,823）の一部はここで説明できる可能性がある。
- 給餌と水やりはどちらも「移動が長い」ことが原因と見られる。作付けと家畜の配置を
  shed の近くに固めるだけで両方に効くかもしれない。次の実験で測る。

## 次のアクション

1. 実行層の改善を1つずつ `eval.py` で測る（基準：`main.py` の現行版に対してペア差がプラス）。
   - (a) 家畜・作物を shed の近くに固めて配置する
   - (b) 餌の運び役を増やす／多めに持たせる
   - (c) 水やり担当を「未水やりが多い区画」に割り当てる
2. 上の (a)〜(c) で逃走ゼロ・枯死5%以下を満たしたら、`tests\test_eval.py` の
   `test_baseline_loses_no_animals`（現在 xfail）を通常のテストに戻す。
3. そのうえでフェーズ1（マクロ模倣）に進むか判断する。
