## 考察

- **公開エージェントは v2 と桁違いに強い。** v2 の改善を積み重ねて届く差ではない（v2 の1回の改善は +14k、ここは +80k）。
  銅を狙うなら、公開エージェントを土台にするのが現実的。
- **手元の5本の中では v16rc5 が最強**（91.2%）。rayk_c54 が次点で、v16rc5 との直接対決も 14-26 と競っている。
- **勝率と所持金の差は一致しない。** rayk_c54 対 rayk_c46 はペア差 +226 しかないが 35-5。
  レーティングが勝敗だけで決まるなら（rayk の記述。未検証）、評価は試合勝率で見るべき。
- **注意（手元の強さ ≠ リーダーボード）：**
  - 相手は手元の5本だけ。本番の相手はずっと多様で、公開エージェントのコピーを出しているチームも多いはず。
    同じコピー同士では勝ったり負けたりで、レーティングは頭打ちになりうる。
  - v16rc5 は上位提出の行動列を再生する作りに見える（相手に合わせて変えない部分がある）。
    手元の5本に強くても、違う型の相手にどうかは提出してみないとわからない。
  - rayk の「C92 は 2836.8」はノートブック作成時点の値。今の順位は提出して測るしかない。

## 結果3：v16rc5 の提出前確認（doc 05 §4 / doc 06）

ADR-0003 承認後、`submissions\v16rc5\main.py` に**改変なしで**取り込んだ（SHA-256 `f029fa0c…` がノートブックの
`expected_sha256` と一致。tar の中身も同じハッシュ）。

| doc 05 §4 の基準 | 結果 | 判定 |
|---|---|---|
| 直前の提出版（v2）に対しペア差が標準誤差の2倍以上プラス | +80,372 ± 3,804（試合 40-0） | ✓ |
| starter に 19/20 ペア以上 | 20/20、+152,948 ± 5,136 | ✓ |
| 1ターン推論の最悪 < 50ms | preflight 720ターンで **最悪 1.26ms**（中央値 0.09ms） | ✓ |
| 例外ゼロ | 0件 | ✓ |
| 家畜の逃走ゼロ・最終 shed < 100 | 逃走 0・shed 0 | ✓ |
| 水切れ枯死＋未収穫損失が植え付けの5%以下 | 5 / 192 = 2.6% | ✓ |

- `eval.py -j 1`（5ペア）では最悪 65.4ms と出たが、同じ計測で v2 も 65.7ms。
  単独で3試合×720ターン測ると最悪 3.6ms、20ms を超えるターンは0回だったので、計測時の一時的な停止と判断した。
  正式な判定は preflight の 1.26ms。
- preflight（`--main submissions\v16rc5\main.py`、720ターン）は全項目 OK。tar は `main.py` 1枚、11,658 bytes。
- rayk_c54 は preflight の「壊れた観測でも落ちない」で観測 `None` に `AttributeError` を出すので、今回は提出しない。
