## 仮説

EXP-20260919-07 の事前確認どおり、LightGBM の状態モデルは6ヘッド（種5・土地1）すべてで
3つの比較対象（日中央値・現状維持・ルール表 v2）の最良を上回る。

## 設定

- データ：`data\dataset\macro.csv`（`scripts\build_dataset.py`、rank は `leaderboard.csv` から引き直し済み）
  **9,976 行 / 207 エピソード / 50チーム**、特徴量49個
- モデル：LightGBM 4.7.0、ヘッドごとに1モデル。`num_leaves 7` / `learning_rate 0.08` /
  `min_data_in_leaf 20` / 最大200本。回帰は L2、土地は binary。重みは `weight` 列（rank ＋チーム均し）
- 検証：エピソード単位 `GroupKFold` 5分割。**early stopping は学習側 fold の 20% のエピソードで行う**
  （評価用 fold で止めると CV が甘くなるため）。最終モデルの木の本数は各 fold の最良本数の中央値
- 比較対象の定義は EXP-20260919-07 と同じ（ルール表は `agent/macro.py` の `PARAMS` から読む）

```cmd
.venv\Scripts\python.exe scripts\train_macro.py
```

## 結果2：実行時に効く値で測り直した MAE

`decide_market` は「目標 − 保有 > 0 のときだけ買う」ので、保有より下の予測は実害が無い。
また §3.5 で予測は整数に丸める。そこで全予測器を **`max(保有, round(予測))`** に変換して測り直した
（使い捨てスクリプト、リポジトリ外）。

| ヘッド | 状態モデル | 日中央値 | 現状維持 | ルール表(v2) | 判定 | 買った日の割合 |
|---|---|---|---|---|---|---|
| WHEAT | **1.976** | 4.548 | 5.269 | 8.881 | 上回る | 78.5% |
| CARROT | **0.913** | 1.701 | 1.364 | 1.366 | 上回る | 22.2% |
| TOMATO | 0.258 | 0.426 | **0.204** | **0.204** | 下回る | 6.7% |
| STRAWBERRY | **0.596** | 2.547 | 1.170 | 8.951 | 上回る | 21.6% |
| MELON | 0.273 | 0.425 | 0.483 | **0.258** | **下回る** | 8.5% |

- **MELON は、実行時の値で見るとルール表に負ける。** ルール表の MELON は「day 0〜1 に12、以降は0」で、
  実行時は `max(保有, 0)` になり、事実上「序盤に12買って以降は買わない」。上位勢の実際とほぼ同じ。
- 最初は上限に「hour 0 の空きタイル数」も入れて測ったが、これは誤り。`decide_market` は毎ターン空きを
  数え直し、日中に収穫で空いたタイルにも植えるので、上位勢は hour 0 の空きより多く買っている。
  オフラインでは再現できないので上限は外した。

## 考察

- **学ぶ価値がはっきりあるのは WHEAT・CARROT・STRAWBERRY・土地の4ヘッド。**
  どちらの測り方でも比較対象の最良を大きく上回る（WHEAT は実行時の値で 4.55 → 1.98）。
- **TOMATO と MELON は、買う日がそれぞれ 6.7%・8.5% しかない。** ほとんどの日は「買わない」が正解で、
  モデルは時々余計に買う予測を出して負ける。ルール（TOMATO は買わない、MELON は序盤だけ）で十分。
- 生の MAE は、実行時には効かない「保有より下の予測」と端数も誤差として数えている。
  **合否は実行時に効く値で判定するほうが実態に合う。** ただし最終判定はどちらにしても
  `scripts\eval.py` のペア差（1-4）。
- WHEAT と STRAWBERRY は上限の200本まで early stopping がかからなかった。本数を増やす余地はあるが、
  1-4 の対戦評価の前に詰める理由は無い。
