## 仮説と検証条件

v13 は v51 に候補A3の判定を足しただけなので、v12 と行動・最終所持金が一致するはず。
一方、自分と相手の農場を比較する方式で v9/4 系を見抜けるかは未確認。
コピー系で判定が出ない場合、第3段の実装には進まない。

## 方法

- コピー系5本：gods_mode / peak_2950 / smaller_market_shock / yummers / thomas_v94_safe。
- 比較用9本：v49 / v50 / v47 / metav4_v13 / tetsutani_ms / tetsutani_dpts / tetsutani_dpts_b / tetsutani_shop / farming_v2。
  ここで「別系統」は狙っている v9/4 コピー系以外という意味。v49・v50・v47 は v51 の近縁である。
- seed 241〜250、各両席、相手ごとに20試合を v12 / v13 で別々に実行。合計560試合、280組の比較。
- Python 3.14.4 / kaggle-environments 1.32.7。4並列で開始し、54組の保存後に8並列で再開。
  保存済みの組を除外し、最終集計で相手・seed・席の重複がないことを確認。推論時間の合否評価には使わない。
- 先に gods_mode / v49 × seed 241 × 両席（v12 / v13 合計8試合）の少量確認を実施。
- `scripts.eval.resolve_agent` の最後の callable 選択と `_TimedAgent` の引数切り詰めを使用。
  試合ごとに新しい名前空間を読み込み、複数ファイル相手の補助モジュールも再読込して状態共有を防ぐ。

  安全包みの内側の例外も計数する。観測・返却行動は変更しない。
- 両者の最終所持金を数値で厳密比較し、全720ステップの両者の行動を正規化JSONの SHA-256 で照合。

## 考察と次のアクション

1. 当初懸念した「v51 は別系統なので農場が一致しない」は、今回のコピー系100試合では起きなかった。
   **全試合で農場は96〜167の72ターン一致していたが、所持金差が変わって判定から外れた。**
   逆に比較用相手の多くでも農場が一致し、所持金差が一定なら発火した。
   tetsutani_shop だけは全20試合で step 98 に農場が不一致になった。
2. 判定の実装不良や計測の不発ではない。単体テストの固定差ケースと実戦90試合で発火を確認した。
   **「自分と相手の序盤の農場・所持金差が同じ」は「相手が v9/4 コピー系である」の代わりにならない。**
   ADR-0004 本文の「判定は土台に依存しない」という想定は、この用途では成立しない。
3. **第3段は停止。先回り層も判定の緩和も実装していない。** 単純に所持金差の条件を外すと、今回の
   比較用でも8本160試合の農場が窓全体で一致するため、対象の識別は改善しない。
4. 第1段の v12 は引き続き独立した提出候補だが、今回提出の判断はしていない。
   コピー狩りを続けるなら、対象を識別する方法と先回りが効く根拠を新たな doc / ADR で検討・承認してから。
5. 結果の範囲は手元14本・seed 241〜250・両席。別 seed や本番全体の発火率を断定するものではないが、
   現行第3段の前提を否定する反例としては十分。roadmap 3-18・ADR-0004 の進捗・handover に反映。
