## Runtime history that should not be repeated

v147 initially appeared to have candidate-specific >1s tails. Later paired GC diagnostics showed extreme maxima can be GC-sensitive and may occur in the control too. cProfile still established `_v111_reorder` candidate enumeration as a real hot path.

A duplicate-factor cache was tested and rejected: only 72 duplicates among 436,786 evaluated candidates (~0.0165%); heavy 20,160-candidate turns had no useful duplicate concentration.

v150 instead skipped a redundant second pass when the parent v111 pass made no change. This preserved tested semantics and reduced v111 evaluations by roughly 18-22% on focused/burned/sealed panels.

Do not reopen the duplicate-cache idea without new evidence.
