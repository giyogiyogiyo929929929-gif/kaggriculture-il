# ADR-0003: 銅メダルに向けて、公開エージェントを提出の土台にする

状態: Accepted（2026-09-19 ユーザー承認。ルール・ライセンスと最終順位の扱いの確認を依頼したうえでの承認）
日付: 2026-09-19
関連: ADR-0002, EXP-20260919-10, roadmap.md（銅メダル）, 05_evaluation.md, 06_submission.md

## 背景

- 目標は銅メダル（上位10%）。2026-09-19 時点で 9,486 チーム、**銅ラインは 948位・スコア約 2,387**。
  締め切りは **2026-09-30**。自前の v2 は 526.5（6,541位）。
- ADR-0002 で、マクロ模倣を本線から外し、実行層（ルール）の改善に集中すると決めた。
  ただし v2 の1回の改善は +14k 程度（EXP-20260919-05）で、11日で銅に届く見込みは低い。
- 公開ノートブックの上位エージェント6本を手元で評価した（EXP-20260919-10）：
  - **6本すべてが v2 に 40-0 で全勝**。所持金は v2 の約3.5倍（例：v16rc5 121,810 対 36,240）。
  - 総当たりでは **v16rc5 が 146勝14敗（91.2%）で最強**、rayk_c54 が 120-40（75.0%）で次点。
  - ノートブックの記述では、rayk の C92（= rayk_c46。総当たりでは3番手）が public score 2836.8 に達した（未検証）。

## 決定

1. **提出の土台を公開エージェントにする。** 第1候補は `boatlee/v16-rc5-high-score-8c-4s-premium-market-lead`（v16rc5）、
   第2候補は `raykkretzschmar/kaggriculture-findings-from-zero-to-top-meta` のセル54（rayk_c54）。
2. **出どころを残す。** 取り込むソースはノートブックから取り出したものを**そのまま**置き、先頭に出典（ノートブック・作者・取得日・
   取り出し方・SHA-256）を書いたファイルを添える。改変は別ファイルで行い、差分がわかるようにする。
3. リポジトリの配置（案）：
   - `submissions\<名前>\main.py`（公開エージェント本体。そのまま）＋ `submissions\<名前>\SOURCE.md`（出典）
   - 自前の `main.py` + `agent\`（v2）は残す（比較対象・保険）
   - `scripts\preflight.py` に `--main <パス>` を足し、どの候補でも同じチェックと tar 作成を通せるようにする。
     あわせて、**Kaggle と同じく引数の数に合わせて呼ぶ**ように直す（v16rc5 は `agent(obs)`。今の preflight は2引数で呼ぶので落ちる）。
4. **評価の軸に「試合勝率」を足す**（doc 05）。レーティングは勝敗だけで決まるという指摘があり（rayk、未検証）、
   実際に rayk_c54 対 rayk_c46 はペア差 +226 なのに 35-5 だった。合否は「直前の版に対する試合勝率」と
   「公開エージェント群との総当たり勝率」で見る。
5. **提出の順番**：まず v16rc5 を提出してレーティングを測る。同日中に rayk_c54 も出して比べる（1日5回まで）。
   その後の改善は、選んだ土台を凍結したものに対して `eval.py` で測る。

## 検討した他の案

- **v2 の改善だけで進める（ADR-0002 のまま）。** 公開エージェントとの差が +80k あり、11日で埋まる見込みが低い。
- **rayk_c46（C92）を土台にする。** 2836.8 の実績の記述があるが、手元の総当たりでは v16rc5 に 0-40、rayk_c54 に 5-35。
- **公開エージェントの行動を模倣学習する。** 強いお手本は手に入ったが、フェーズ1の失敗（状態のずれ）がそのまま当てはまり、
  コードをそのまま使えるのに学習で近似する理由が無い。

## 結果・トレードオフ

- 銅に届く可能性が大きく上がる。ただし**手元の強さはリーダーボードを保証しない**：
  - 相手は手元の5本だけ。多くのチームが同じ公開エージェントを出していれば、コピー同士でレーティングが頭打ちになる。
  - v16rc5 は上位提出の行動列を再生する作りに見え、違う型の相手への強さは提出して測るしかない。
- 「模倣学習エージェント」というリポジトリの当初の方針からは外れる。学習基盤（ダイジェスト・学習テーブル・eval）は、
  公開エージェントの改善の検証に引き続き使う。
