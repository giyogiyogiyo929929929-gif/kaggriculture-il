# ADR-0002: マクロ模倣を本線から外し、実行層（ルール）の改善に集中する

状態: Accepted（2026-09-19 ユーザー承認）
日付: 2026-09-19
関連: ADR-0001（これを Superseded にする）, 04_model_design.md §3.7, EXP-20260919-09, EXP-20260919-08, EXP-20260918-01

## 背景

ADR-0001 で「日単位の戦略判断（購入・土地など）だけを模倣し、ミクロはルールで実行する」と決めた。
フェーズ1でこれを実装し、doc 04 §3.7 に撤退条件を先に決めておいた
（「1-4 でペア差が標準誤差の2倍に届かない、またはマイナスなら提出しない。ADR-0002 を書く」）。

結果（EXP-20260919-09）：

- 模倣モデルは v2 に **−6,801 ± 1,742（4勝16敗、20ペア）**。標準誤差の約3.9倍マイナスで、撤退条件に当たる。
- 主因は種の目標（種だけ −5,300、土地だけ −1,552 は誤差の範囲）。
  モデルは上位勢の「保有量の水準」を真似るため、自分の軌跡では終盤に実らない STRAWBERRY を買い、
  終盤の CARROT を買わなくなった。
- オフラインでは上位勢と非常によく一致していた（EXP-20260919-08）が、それは強さを予測しなかった。
- これは EXP-20260918-01 の「上位勢同士ではマクロ行動で勝敗が説明できず、差は実行層にある」と整合する。

## 決定

1. **マクロ模倣を本線から外す。** 提出版は v2（ルール表）のままにする。
2. **以後は実行層（ルール）の改善に集中する。** 候補は既に doc 04 §5.6 と EXP-20260919-05 / -09 にある
   （単価の高い仕事を増やす、`FERTILIZE`、価格を見た売却、`stop_planting_day`、終盤の STRAWBERRY の購入停止）。
3. フェーズ1で作ったものは**消さずに残す**が、提出物からは外す：
   - `main.py` は `plan` を渡さない（v2 と同じ挙動）。`decide_market(plan=None)` が v2 と同一であることはテスト済み
   - `SUBMISSION_PATHS` から `models/macro.json` を外す。preflight のモデル確認は、`main.py` がモデルを使うときだけ行う
   - `scripts\build_dataset.py` / `scripts\train_macro.py` / `agent\plan.py` はそのまま残す
     （上位勢の行動分析や、将来の別の定式化の実験に使える）
4. doc 04 §3 を `Deprecated`（フェーズ1の設計として）にし、ADR-0001 を `Superseded by ADR-0002` にする。

## 検討した他の案

- **ラベルを「保有量」から「購入量（差分）」や「作物ごとに今植えて間に合うか」に変えてやり直す。**
  分布のずれの直接の原因には効く可能性がある。ただし EXP-20260918-01 の事実（マクロでは勝敗が説明できない）
  がある以上、上位勢に近づけても伸びしろは小さいと見込む。ルール側の明確な改善候補
  （終盤の STRAWBERRY など）を先に片付けたほうが期待値が高い。**否定はしない。**やるなら新しい ADR で。
- **土地ヘッドだけ残す。** 土地だけモデルは −1,552 ± 1,265 で誤差の範囲内。v2 を上回る根拠が無いので採らない。
- **撤退条件を緩めて調整を続ける。** 撤退条件は、結果を見てから線を動かさないために先に決めたもの。
  動かさない。

## 結果・トレードオフ

- 学習・データ基盤（ダイジェスト → 学習テーブル → LightGBM → 純 Python 推論）は残るので、
  別の定式化を試すときの費用は小さい。
- 提出は v2 のまま。publicScore の改善は実行層の改善に依存する。
- ミクロ（実行層）はルールなので、上位勢の細かい作業効率を取り込む手段は当面なくなる
  （ADR-0001 と同じトレードオフが残る）。
