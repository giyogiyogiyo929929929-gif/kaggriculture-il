## 1. 目的

**v9/4 のコピーに 50% より多く勝ち、ほかの公開エージェントへの勝率は落とさない版（v5 以降）を作る。**

背景（確認済みの事実）：
- 最終順位は、締め切り（2026-09-30 23:59 UTC）後2週間の対戦にもとづく **Bradley-Terry トーナメント1回**で決まる。
  チームの成績は有効な2枠のうち良いほう。引き分けは双方 0.5 勝（doc 06、主催者の回答）。
- v4（v9/4＋包み）は公開上位11本に負け越さない。最も手強い V47 / V48 系に 70%（EXP-20260919-13）。
  **訂正（EXP-20260919-15）**：seed を 40 に増やすと v47 に約 90%（72勝8敗）。70% は seed 1〜10 の偏り。
- **v9/4 は 2026-09-19 に公開され、既にコピー（master-engine-v3）がある。** 公開ノートブックの締め切り（9/23）までに
  コピーは増えると考えるべき。**v9/4 同士は必ず引き分けになる**（下の §2 の事実1）。
- したがって、コピーの大集団の中で順位を上げるには、**コピーとの試合を引き分けから勝ちに変える**のが最も効く。

## 2. 確認済みの事実（この計画の前提）

1. **v9/4 同士の試合では、720ステップすべてで両者の農場が完全に同じ**（タイル・所持金・本人と作業員の位置）。
   行動も 719ターンすべて同一。結果は同額の引き分け（seed 4 で確認、2026-09-19）。
   **訂正（EXP-20260919-14）**：雑草は両者で別々の乱数で生えるため、20シード中6シードは 168ステップ目に食い違い、
   うち4シードは引き分けにならない（席によって ±600〜1,300 の運の差）。残りの大半は同額の引き分け。
2. **v9/4 と V47 / V48 / First in Line の試合では、1ステップ目から農場が食い違う**（同上）。
3. 市場の注文は両者のリストを1件目から交互に1個ずつ執行する。プレミアム品（STRAWBERRY・MILK・WOOL・MELON）は
   余剰 60〜160個で $1 まで落ち、**先に売った側が高値を取る**（thomas のノートブック §4.4・4.5。作者の主張、未検証）。
4. 同じコードでも提出ごとのレーティングは ±100 ほどぶれる（thomas §8）。**判断は手元の直接対決で行う。**
5. thomas が試して**失敗した**こと（§7）：トマトの上乗せ、売りを遅らせて高値を待つ、V48 への載せ替え、
   途中から適応型の計画に切り替える、など。**同じことは試さない**（試すなら理由を書く）。

## 3. 改善の候補（優先順）

### 候補A：コピー相手を見抜いて、引き分けを勝ちに変える（最優先）

**2026-09-19 改訂：探索の結果（EXP-20260919-14）で方式を確定した。** 当初の案（A1〜A3、判定の切り替え）は下の方式に置き換える。

- **判定**：毎ターン、**雑草タイルを空きとみなした** `farms[自分]` と `farms[相手]` を比べる（タイル・所持金・位置など全項目）。
  一度でも違えば、その試合では二度と反応しない。**167ステップ目まで一致し続けたらコピーと確定**し、以後は比べない。
  - 雑草を無視する理由：雑草は両者で別々の乱数で生え、v9/4 同士でも 168ステップ目に食い違う（20シード中6）。
  - 167 で確定する理由：7日目（168）より前の食い違いは20シードで0件。売りの予約は 192 からなので効果は変わらない。
    確定後は比べないので、自分が動きを変えても判定は崩れない（当初の `TODO(要確認)` はこれで解消）。
- **動き**：コピーと確定した後だけ、v9/4 の売りの先読み幅（`V9_RACE_DEFAULT` / `V9_RACE_MAX`、通常 40〜48）を
  **呼び出しの間だけ 52 に固定**する（呼び出し後に元に戻す）。v9/4 自身の仕組みの定数を変えるだけで、ほかの判断は変えない。
- **実測**（v4 相手、選ぶのに使っていない seed 11〜30、40試合）：**28勝10敗2分**。
  誤発動：コピー（master_v3）では 2/2 発動、別系統11本ではすべて 0。

### 候補A2：コピーの PREDICT を1ターン先回りする（Implemented 2026-09-19）

根拠：EXP-20260919-14 結果4・5。

- **わかったこと**：v5 がコピーに負ける売りは、値段が基準値以下（先読みの予約が止まる場面）で起きていて、
  その 68/74 塊は v9/4 の **PREDICT 層**（`_v92_predict`）の発火による。PREDICT は、相手の売りの時期を毎ターン復元し、
  内蔵の記録（上位チームの売りの時系列）と照合して「相手が次の2ターンで4個以上売る」と予想すると、
  テープで48ターン以内に売る予定の分を今すぐ売る。値段では止まらない。
  v5 が売りの時期を変えるとコピーの予想が変わり、コピーの PREDICT が先に発火する（v4 が先 39塊 −3,477、v5 が先 29塊 +2,882）。
- **やること**：コピーと確定した試合だけ、**コピーの PREDICT が次のターンに発火するかを自分で計算し、発火するなら同じ売りを1ターン前に出す**。
  - コピーが見る「こちらの売り」は、こちらが前のターンに実際に売った数（RACE の `prev["own"]`、値段 > 3・2個以上）。
  - これに v9/4 自身の `_v92_p_forecast`（同じ内蔵記録・同じ町の店）を当て、コピーと同じ周期（3ターンごと）で最良の記録を選ぶ。
  - 次のターン t+1 にコピーが見る2ターン（t+2・t+3）で4個以上なら、その品の「t+1 から48ターン以内のテープの売り」を今売る
    （個数は在庫まで）。売る品がこのターン既に注文にあれば何もしない。v9/4 の PREDICT と同じ規則を1ターン前にずらしただけ。
  - コピーと確定していない試合では何もしない（v5 と同じ）。
- **探索の結果**（v4 相手、seed 11〜30、40試合）：1ターン前 **37勝3敗0分（差の平均 +838）**、2ターン前 35勝5敗、v5 は 28勝10敗2分（+40）。
  → 1ターン前を採用。確認（seed 51〜70、40試合）：1ターン前 **40勝0敗0分（平均 +1,545）**、v5 は 28勝6敗6分。
- **置き場所**：`submissions\v6_preempt\main.py`（v5 の中身 ＋ この層 ＋ 安全包み。v9/4 原本の部分はバイト単位で同一）。
- **受け入れ条件（v6 を提出してよい条件）**：
  - [x] v4 相手、**どこにも使っていない seed 71〜90**（40試合）で勝ち − 負け ≥ 10、かつ同じ seed の v5 より勝ち − 負けが多い
    （seed 1〜70 は探索・確認に使った）→ **v6 35勝5敗0分（+30、平均 +1,050）**、v5 30勝8敗2分（+22、平均 +136）
  - [x] 別系統11本（§5）との試合で、所持金が v4 と試合ごとに完全一致（各10ペア）→ 220/220 試合で完全一致
  - [x] master_v3（コピー）に v5 以上の成績（10ペア）→ **20-0-0**（v5 は 12-2-6）
  - [x] preflight 全項目 OK、例外0。コピーモードの1ターンの最悪も 1プロセスで 200ms 未満
    → preflight 最悪 68.10ms・99%点 9.21ms。コピーモード（v4 相手 1プロセス 2試合 1,438ターン）：99%点 10.64ms・最悪 55.55ms
  - [x] テスト（原本部分のバイト一致、コピー未確定では何もしない、例外時に元の行動を返す）→ `tests\test_v6_preempt.py` 8件
  - [x] EXP に記録 → EXP-20260919-14 結果5・6

### 候補A3：コピー判定をゆるめ、「コピー＋序盤の小さな上乗せ」にも勝つ（Implemented 2026-09-20）

根拠：EXP-20260919-17。

- **わかったこと**：公開ノートブック「A Smaller Market Shock」（v9/4 ＋ 序盤に小麦を1回多く育てる）は、v4・v6 に **20戦20勝（すべて +50）**。
  80ステップ以降は**所持金だけが違う v9/4 のコピー**だが、v6 の判定は「0〜167 ステップで所持金も含めて完全一致」なので発動しない。
  コピーが増えれば、こうした「コピー＋小さな上乗せ」も増えると考えられる。
- **やること**：判定を「**96〜167 ステップで、雑草と所持金を除いた農場が一致し、かつ所持金の差（自分 − 相手）が一定のままなら、コピーと確定**」に変える
  （96 より前は比べない。序盤の上乗せは 80 ステップまでに終わる）。確定後の動き（候補A・A2）は変えない。完全なコピーは差が 0 で一定なので、今までどおり発動する。
- **所持金の差が一定であることを条件にする理由**（EXP-20260919-17 結果3・4）：所持金を比べないだけの判定（rx96）は、
  強い公開エージェントの多く（V47 系・v31〜v41・v50・market_rhythm）にも発動し、market_rhythm には v6 より 4敗多かった（seed 11〜40）。
  強い相手は 96〜167 ステップの農場が v9/4 と同じだが、売り買いが違うので所持金の差が毎ステップ動く（3〜17種）。
  smaller_market_shock は同じ手を打つので差が 50 のまま動かない。差の大きさでは分けられない（別系統でも 40〜55 のことがある）。
- **探索の結果**：rx96（差が一定の条件なし）は smaller_market_shock に **20-0-0（平均 +1,353、最小 +330）**（v6 は 0-20）。
  **rx96c（差が一定の条件あり）：smaller_market_shock に 20-0-0、ほかの 18本・v4（seed 71〜90）・market_rhythm（seed 11〜40）では
  所持金が v6 と試合ごとに完全一致**（発動していない）。
- **置き場所**：`submissions\v7_relax\main.py`（v6 の判定の部分だけを変える。v9/4 原本の部分はバイト単位で同一）。
- **受け入れ条件（v7 を提出してよい条件）**：
  - [x] smaller_market_shock に、**どこにも使っていない seed 91〜110**（40試合）で勝ち − 負け ≥ 10 → **40-0-0（平均 +1,023）**
  - [x] v4 相手、seed 91〜110 で v6 以上の勝ち − 負け → v7 40-0-0、v6 40-0-0（平均 +1,074 で同じ）
  - [x] smaller_market_shock と v4 以外の手元の公開エージェントで、**所持金が v6 と試合ごとに完全一致**
    → 19本（master_v3 を含む）・各20試合、**380/380 試合で完全一致**
  - [x] preflight 全項目 OK、例外0、コピーモードの1ターンの最悪が 1プロセスで 200ms 未満
    → preflight 最悪 49.29ms・99%点 11.14ms。コピーモード（smaller_market_shock 相手、1プロセス 2試合 1,438ターン）：99%点 10.39ms・最悪 130.85ms
  - [x] テスト → `tests\test_v7_relax.py` 13件（全体 185件が通る）
  - [x] EXP に記録 → EXP-20260919-17 結果6
- **実装（2026-09-20、Implemented）**：`submissions\v7_relax\main.py`（`SOURCE.md` に SHA-256）。組み立て：`scripts\build_v7_relax.py`。
  テスト：`.venv\Scripts\python.exe -m pytest tests\test_v7_relax.py`。評価結果：`data\eval\v7\`。

### 候補B：V47 / V48 系への負け（30%）の原因を突き止めて直す（分析済み・実装しない）

- v4 が V47 / V48 系に負けた試合（EXP-20260919-13 の各6試合）を、EXP-20260919-12 と同じ手順で分析する
  （日ごとの所持金の差、売り買いの比較。**勝った試合も分析し、なぜ勝てたかを書く**）。
- 直すかどうかは原因を見てから決める。thomas の失敗リスト（§2 の事実5）に当たるものは避ける。

  「30%」は seed 1〜10 の偏りだった。負けは小差（−39〜−567）で原因も seed ごとに違う（羊毛が基準値 $200 付近に落ちたときの先行争い、
  小麦の大量売買の買値の差）。直すには v9/4 の基本の判断を変える必要があり、コピー相手を含むすべての試合に効くので、**実装しない**。

## 7. 提出の運用

- **有効なのは直近の2つ**（doc 06）。v5 を出すと、古いほうの v3 が外れ、**v4 と v5 が有効な2枠**になる。
  **2026-09-19 更新：v5 は出さず、v6（候補A2）を出す。** v4 と v6 が有効な2枠になる（v6 はコピー以外には v4 と同じ動き）。
  ~~2026-09-20 更新：v7（候補A3）を出すと、古いほうの v4 が外れ、v6 と v7 が有効な2枠になる。~~
  **訂正（2026-09-20、チーム結成）：いまのチームの有効枠は v6 と k256net の 56357787（1618.9）。v7 を出すと
  56357787 が外れ、v6 と v7 が有効な2枠になる。出す前にチームメイトと合わせる（doc 06）。** v7 は v6 と同じ動きに加えて
  「コピー＋序盤の上乗せ」にも勝つので、v4 を残す理由は無い（v4 はどの相手にも v6 以下）。
- その後 v6 を出すと**古いほうの v4 が外れる**（弱いほうではなく古いほう）。v4 を残したいときは、v4 を出し直す必要がある
  （出し直すとレーティングは 600 から。ただし最終順位はトーナメントなので、レーティング自体は最終順位に効かない）。
- 締め切り 2026-09-30 23:59 UTC（＝ 10-01 08:59 JST。ユーザーの運用上は「10/1 朝9時」。doc 08 §0）。**最終日の前日までに、残したい2本を有効な2枠にそろえる。**
- 提出コマンドの実行はユーザー（Claude の提出は自動許可で止められる。doc 06）。
